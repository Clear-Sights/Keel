# DL-08 CONFIRMED [dispatch/break] plugin/keel/wire.read_stdin (returns "" for empty bytes); dispatch.main `event = json.loads(raw or "{}")`; plugin/hooks/dispatch.sh fail_open

## claim
dispatch.py module docstring + _open_not_evaluable: "a fail-open written only to stderr is, from every seat, byte-identical to a clean pass" -- hence every fail-open must carry a `systemMessage`; and the shim's "carriage still fails OPEN but stops failing invisibly", asserted by tests/test_shim_visibility.py.

# contrast, the loud paths:
printf '   ' | KEEL_STATE_DIR=$ST CLAUDE_PLUGIN_ROOT=$P bash $P/hooks/dispatch.sh

KEEL_PYTHON=nope KEEL_STATE_DIR=$ST CLAUDE_PLUGIN_ROOT=$P bash $P/hooks/dispatch.sh </dev/null

## observed
Empty stdin (and `</dev/null`) -> stdout `{}`, rc=0, EMPTY stderr, no systemMessage, and the state directory contains no decisions.jsonl at all: three tool calls allowed without being checked, leaving zero trace anywhere.
By contrast whitespace stdin -> {"systemMessage": "keel: this call was ALLOWED WITHOUT BEING CHECKED -- the event could not be read (JSONDecodeError)..."}; truncated JSON -> same loud form; missing interpreter -> {"systemMessage":"keel hook wiring fault: interpreter not found"}; planted SyntaxError in dispatch.py -> {"systemMessage":"keel hook wiring fault: Python dispatcher failed"}; bad plugin root -> loud. So every fault the design anticipated is loud, and the single input that produces a SILENT unchecked allow is the one a broken pipe, a closed stdin, or a host that fails to write the envelope produces -- exactly the "silent wiring death this shim exists to prevent". A host wired this way is indistinguishable from an uninstalled plugin.
